## আপনার অনুমোদিত কাজ

Password ছাড়াই User ID দিয়ে signup; আপনার approval না পাওয়া পর্যন্ত Pending। একটি ID একটি TV অথবা mobile-এর সঙ্গে বাঁধা থাকবে। একই device-এ পরেরবার login লাগবে না। আপনি block করলে access বন্ধ হবে। TV remote ও mobile touch দুটোতেই একই অ্যাপ চলবে। আগের autoplay, first channel, last channel, playlist refresh, favorites এবং backup playback থাকবে। Permanent production signing key এবং আগে শনাক্ত করা update/player fixes অন্তর্ভুক্ত।

Backend এবং admin panel Vercel-এ থাকবে—hosting-এর database quota শেষ হওয়ায় আপনি এই hosting option নির্বাচন করেছেন। TV-এর আলাদা Neon Postgres database হবে; existing billing hosting-এ database লাগবে না। Target release: v1.1.0, versionCode 2, Android 6/API 23 বা পরে।

## পদ্ধতি এবং প্রস্তাবিত নির্বাচন

Selected: পৃথক TypeScript/Node.js API এবং responsive admin panel Vercel-এ, persistent Neon Postgres database-সহ; installation key দিয়ে device proof। backend/ নামে app repository-তে deployable project থাকবে। Vercel project-এর Root Directory হবে backend। Database transactions uniqueness, challenge consumption এবং reset/revocation সুরক্ষিত করবে। DATABASE_URL, ADMIN_PASSWORD_HASH এবং SESSION_SECRET server environment-এ থাকবে। Filesystem/in-memory state persistent database হিসেবে ব্যবহার হবে না।

Vercel ও Neon connection/provisioning live deployment-এর prerequisite। Current plans/usage limits দেখে owner-এর approval ছাড়া paid resource নেওয়া হবে না। Public TV website ও playlist-এর ঠিকানা অপরিবর্তিত থাকবে।

## Signup ও device binding

- ID: 3–32 ASCII letters, numbers, underscore, dot বা hyphen; surrounding whitespace বাদ এবং lowercase canonical identity। উদাহরণ: Rony এবং rony একই account।
- App Android Keystore-এ EC P-256 installation key তৈরি করবে। Private key app থেকে export হবে না। Server শুধু public key রাখবে। Android device brand/model তথ্য পরিচিতির জন্য; authorization-এর প্রমাণ নয়।
- Signup public key possession proof দিয়ে হবে। Server unique normalized ID এবং public-key fingerprint atomic transaction-এ reserve করবে। একই device retry করলে একই Pending request ফেরত আসবে; ভিন্ন key দিয়ে duplicate ID নিলে reject হবে।
- Admin Pending list-এ user ID, TV/mobile, device model, request time ও key fingerprint-এর সংক্ষিপ্ত পরিচিতি দেখবে। Approval ওই নির্দিষ্ট key-তে বাঁধা থাকবে।
- Server-issued single-use random challenge 60 seconds পরে expire হবে। Client action, account ID এবং request-body hash-সহ নির্ধারিত message sign করবে; server SHA256withECDSA verify করে nonce atomically consume করবে। Replay বা অন্য action-এ signature ব্যবহার reject হবে।
- Successful approval/session request 256-bit random opaque token দেবে; server শুধু token hash রাখবে। Protected request-এ token এবং fresh device proof দুটো যাচাই হবে। App encrypted storage ব্যবহার করবে; device credentials backup/restore হবে না।
- Session expire হলে একই device proof দিয়ে স্বয়ংক্রিয় session renewal হবে। User-কে ID আবার লিখতে হবে না। Admin reset/revoke ছাড়া অন্য device takeover করতে পারবে না।
- Reinstall/data clear/device replacement-এর জন্য admin Device Reset প্রয়োজন। Reset পুরোনো binding/session revoke করে account-কে replacement registration-এর জন্য খোলে; নতুন device আবার approve করতে হবে।

## Block, connectivity এবং monitoring — প্রস্তাবিত নির্দিষ্ট নিয়ম

- প্রত্যেক cold start-এ server status check-এর পর playback। Pending অবস্থায় app সামনে থাকলে 10 seconds অন্তর check করে; approved হলে playback শুরু।
- Playback-এর সময় heartbeat প্রতি 60 seconds। Block response পেলে সঙ্গে সঙ্গে player stop ও blocked screen। Online device সাধারণত পরের heartbeat-এ block জানতে পারবে।
- Server unreachable হলে ইতিমধ্যে চলমান approved session সর্বশেষ successful authorization-এর পর সর্বোচ্চ 5 minutes চালু থাকতে পারবে; তারপর playback pause এবং reconnect screen। এতে login prompt ফেরত আসে না; reconnect হলে auto-resume। User এই policy অনুমোদন করেছেন।
- Online metric: শেষ 120 seconds-এ heartbeat পাওয়া foreground device। Today active users unique canonical IDs, Asia/Dhaka calendar day। Watch time client playback heartbeats থেকে conservative estimate; server receive-time delta প্রতি heartbeat সর্বোচ্চ 60 seconds count করবে। Paused/background/blocked অবস্থায় watch time নয়।
- Admin dashboard: total, Pending, approved, blocked, online, today active, app-version counts; per-user last seen এবং approximate watch time। Approval/block/unblock/reset actor এবং timestamp audit log থাকবে।
- Admin login আলাদা password-protected server session; HttpOnly/Secure/SameSite cookie, CSRF protection, login rate limits। এটি end-user signup-এ password যোগ করে না। Admin password ও DB credential APK/repository-তে থাকবে না।

## UI ও playback

- Dark background, red/white XtremeX branding, বড় পড়ার মতো লেখা ও স্পষ্ট focus border।
- TV: direct full-screen playback; tuning-এ 3.5 seconds channel number/logo/name overlay। OK menu থেকে guide, favorites, search, refresh, update—color-button ছাড়া সব পাওয়া যাবে। Side guide খোলা থাকলে playback চলবে।
- Mobile: responsive player-এর নিচে category ও list; fullscreen tap-এ Next/Previous ও menu controls। Portrait/landscape screen-এ controls দৃশ্যমান থাকবে।
- Signup: ID এবং approval request button। Pending/Blocked screen-এ status ও configurable support number; mobile-এ dialer খোলা যাবে।
- Dialog open থাকলে Activity shortcuts বন্ধ: Update/Exit-এর navigation ও OK dialog-ই পাবে। Search field-এ left/right cursor movement category shortcut ধরে ফেলবে না।
- Playlist refresh stable channel identity দিয়ে current channel, previous channel ও source reconcile করবে। Removed current channel হলে channel 1; changed stream হলে updated source retune; unchanged stream হলে playback uninterrupted। Delayed retry পুরোনো tuning generation-এর হলে discard হবে।
- Error copy measured evidence অনুসারে: no network, source unavailable, backup attempt; unsupported conclusion যেমন নিশ্চিত BDIX restriction দাবি করা যাবে না।

## Signing ও app update

- এক permanent production keystore; future production updates-এ একই key ও com.xtremex.tv package। Debug com.xtremex.tv.debug production-এ in-place update হবে না।
- Private keystore repository-তে থাকবে না। প্রয়োজনীয় চার Actions secrets configure করার capability বর্তমান connector-এ নেই; secure owner-side setup guide ও private key handoff প্রস্তুত করতে হবে। New production APK signing verification ছাড়া production ready দাবি নয়।
- SHA-256 বাধ্যতামূলক 64 hex characters; blank/mismatch reject। HTTPS APK URL, downloaded package identity, increasing versionCode ও signing certificate মিলিয়ে installer handoff।
- Download ID এবং expected metadata persist হবে। App restart-এ existing download query করে progress/verify/install resume; duplicate download নয়। Failure বা corrupted APK clean retry সমর্থন করবে।
- Workflow release inputs validate করবে এবং metadata JSON serializer দিয়ে তৈরি করবে। Publish-এর আগে signed APK ও certificate verify; সফল release URL/SHA-256 দিয়ে update.json তৈরি।
- Android installer-এর final install confirmation user দেবেন।

## যাচাই ও practical limits

- Backend tests: duplicate-ID race, challenge replay/expiry, wrong-device proof, Pending denial, approval, block/revoke, reset, CSRF, heartbeat metrics/date boundary। Temporary DB ব্যবহার; live data নয়।
- Android checks: auth state transitions, cached session renewal, lease expiry/reconnect, playlist removal/URL changes, stale retry cancellation, dialog focus, download restart/hash/package/certificate validation।
- CI assembleDebug/assembleRelease ও APK signature verification। Actual TV/mobile playback, installer ও remotes device testing-এর ফল আলাদা করে জানাতে হবে; build success device test নয়।
- App access control public stream URL-কে অন্য player-এ খোলা থেকে আটকায় না। Public playlist/streams protection এই update-এর scope নয়।
- Vercel/Neon connection, final live endpoint এবং admin support number এখনও পাওয়া যায়নি। Backend package/configure guide প্রস্তুত করা যাবে; actual deployment ও end-to-end live test এসব তথ্য ছাড়া শেষ দাবি করা যাবে না।
