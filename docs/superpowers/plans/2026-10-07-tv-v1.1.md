# XtremeX TV v1.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Native inline execution is proposed; do not spawn agents without the user's selected method.

**Goal:** Ship the approved passwordless single-device TV/mobile experience, Vercel approval/monitoring backend and permanent signed update pipeline.
**Architecture:** Android Keystore device proof and revocable opaque sessions gate native playback. A separate Node.js/TypeScript API and responsive admin UI on Vercel persist authorization and monitoring in Neon Postgres. Existing public playlist stays at xtremextv.vercel.app/channels.json.
**Tech Stack:** Existing Kotlin/Media3/Android API 23+, TypeScript, Vercel Node.js functions, pg/Postgres, Node built-in crypto/test, Android JUnit and GitHub Actions.
**Spec:** ../specs/2026-10-07-tv-v1.1-design.md

## Global Constraints

- User ID only; no end-user password, OTP or browser login. Admin has its own protected login.
- One normalized ID = one approved installation; approval required, block/reset revokes access.
- Release v1.1.0/versionCode 2; production package com.xtremex.tv and one permanent signing identity.
- Foreground heartbeat 60 seconds; online threshold 120 seconds; challenge TTL 60 seconds; active-session offline grace 300 seconds; pending poll 10 seconds.
- Asia/Dhaka day boundaries for today's unique users; estimated watch delta capped at 60 seconds.
- No database on existing hosting. No secrets in git/APK, no paid provisioning without owner approval.
- Physical TV/mobile/installer tests remain explicitly unverified unless a device test runs.

## Review Focus

- Concurrent first registration of Rony/rony must bind exactly one installation.
- Replayed or altered signed body must not renew a token or post a heartbeat.
- Resume after background/device reboot must not extend offline grace using wall-clock changes.
- Repeated or delayed heartbeat must not inflate online/watch metrics or cross day boundaries incorrectly.
- Existing download or delayed player retry after process death/channel change must not install or play stale content.

### Task 1: Vercel device authorization API and schema

**Files:** Create backend/package.json, backend/tsconfig.json, backend/vercel.json, backend/api/index.ts, backend/src/{db,identity,proof,accounts,sessions,monitoring,http}.ts, backend/sql/001_init.sql, backend/test/{identity,proof,accounts,monitoring}.test.ts, backend/.env.example, backend/README.md.
**Interfaces:** POST /api/challenge -> {challengeId,nonce,expiresAt}; POST /api/register with {userId,publicKey,deviceType,deviceModel,challengeId,signature} -> {status}; POST /api/session with device proof -> {status,token?,leaseSeconds:300}; POST /api/heartbeat with token/device proof and {playing,appVersion} -> {status,leaseSeconds:300}. Body signing canonical string is action + newline + normalized userId + newline + challengeId + newline + nonce + newline + SHA256(raw payload JSON bytes). Payload field contains the signed JSON bytes as base64; envelope contains challengeId/signature. Challenge is bound to action/account/key fingerprint. Identity proof uses DER ECDSA signature and SPKI DER public key; enforce EC prime256v1 and bounded input sizes.

- [ ] Write failing Node tests for normalization, concurrent unique registration, wrong key, challenge expiry/replay/body alteration, pending denial, token revocation and daily monitoring.
- [ ] Run `cd backend && npm test`; record expected missing-module/assertion failures.
- [ ] Implement migration with accounts(unique user_id, unique bound fingerprint), challenges, hashed sessions, rate limits, admin sessions, heartbeats/daily activity, audit records and settings; all identity mutations and nonce consumption use database transactions. Parameterized SQL only. Enforce signup/key size limits and per-IP request limits in Postgres.
- [ ] Implement the routes and exact DER verification using Node crypto; current status and device generation checked on each authorization. Missing configuration returns explicit 503, never grants playback.
- [ ] Run `npm test && npm run typecheck`; run integration suite against a temporary disposable Postgres database including actual concurrency/replay tests. Mock-only passes do not count as database verification.
